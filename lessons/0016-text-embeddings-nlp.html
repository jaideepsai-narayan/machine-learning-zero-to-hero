1. WHY Do We Need Word Embeddings? (Drawbacks of One-Hot Encoding)

Computers cannot read human text like "cat" or "king". They only process numbers.

⚠️ Drawback of One-Hot Encoding: If your vocabulary has 50,000 words, every word becomes a 50,000-dimensional vector full of zeros except for a single 1.
• Huge memory waste (sparse vectors).
• Zero Semantic Meaning: Dot product between Vector("cat") and Vector("kitten") is 0! The computer thinks "cat" and "kitten" are completely unrelated!
🌍 Real-World Industry Context & Case Studies

Text embeddings power search engines, recommendation systems, and modern AI chat:

  • 🔍 Google Semantic Search & Vector Databases: Search engines convert user queries into dense vectors to retrieve relevant web pages by semantic meaning rather than exact keyword matches.
  • 🛍️ E-Commerce Product Matching: Matching user search terms like "warm winter coat" to product catalog items titled "Thermal Puffer Jacket".
  • 🤖 Large Language Model Input Pipelines: Foundation LLMs (ChatGPT, Claude) process human prompt tokens using learned high-dimensional embedding tables.

2. WHAT IS IT? (Dense Vector Spaces & Word2Vec Geometry)

Word Embeddings (like Word2Vec and GloVe) map words into a dense vector space (e.g. 300 dimensions) where words with similar meanings sit close together!

The Famous Vector Arithmetic Miracle
\[ \text{Vector}("King") - \text{Vector}("Man") + \text{Vector}("Woman") \approx \text{Vector}("Queen") \]

3. HOW Does It Work? (TF-IDF & Word2Vec Skip-Gram Derivation)

A. Term Frequency - Inverse Document Frequency (TF-IDF)

\[ \text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \log\left( \frac{|D|}{|\{d \in D : t \in d\}|} \right) \] Downweights common filler words like "the", "is" and highlights rare key terms.

B. Word2Vec (Skip-Gram with Negative Sampling)

Predict context words given a target center word $w_t$ within window $c$:

\[ \mathcal{L} = \sum_{t=1}^{T} \sum_{-c \le j \le c, j \neq 0} \log P(w_{t+j} | w_t) \] where $P(w_o | w_c) = \frac{\exp(v_{w_o}'^T v_{w_c})}{\sum_{w=1}^{V} \exp(v_w'^T v_{w_c})}$.
🔤 Subword Tokenization, Cosine Similarity & The Polysemy Problem
  • Subword Tokenization (BPE / WordPiece): Modern NLP split words into subword chunks (e.g., "unbeatably" $\to$ ["un", "beat", "ably"]). This prevents out-of-vocabulary (OOV) errors and allows tokenizers to handle any word in human language!
  • Cosine Similarity Retrieval Metric: Measures the angle between two embedding vectors regardless of magnitude:
    • \[ \cos(\theta) = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\| \|\mathbf{v}\|} = \frac{\sum u_i v_i}{\sqrt{\sum u_i^2} \sqrt{\sum v_i^2}} \] Identical direction $= 1.0$, orthogonal $= 0.0$, opposite direction $= -1.0$.
  • The Polysemy Problem (Static vs. Contextual): Word2Vec produces a static fixed vector for every word. Thus, "apple" (the fruit) and "apple" (the iPhone company) share the exact same vector! Contextual embeddings (BERT / GPT) generate dynamic vectors based on surrounding sentence context.

Approach Vector Representation Context Sensitivity Out-of-Vocabulary When to Use
